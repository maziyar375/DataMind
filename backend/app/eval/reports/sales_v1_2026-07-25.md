## Binding constraint

**Generation — and it is model-limited, not a retrieval or prompt gap.**

- Round 1 raised retrieval recall +16 pts and cut policy violations 6→2%, but
  **execution accuracy did not move**. Improving context did not improve
  correctness → retrieval was not the bottleneck.
- After Round 1, **20 of ~31 failures have full (1.0) retrieval recall**: the
  model has every table it needs and still writes wrong-but-valid SQL.
- Round 2 tested the generation side directly (more prompt guidance) and made a
  small model *worse* (parse 98→88%, guard-pass 96→86%, accuracy 36→26%).

Remaining failure modes on full-recall questions: result-shape choices (wide vs
long), time-window interpretation (rolling vs calendar), enum-value casing the
model cannot see (`'Cancelled'` vs `'cancelled'`), and audit-vs-business column
picks (`created_at` vs `signed_up_at`). These are model-capability limits on a
frozen, deliberately-messy set — not closable by prompt/retrieval tuning here.

## Iteration log

### Round 1 — retrieval: FK-neighbour expansion (KEPT)
`app/pipeline/nodes/__init__.py` · `_expand_by_fk`. When the snapshot exceeds
the retrieve budget (26 480 > 24 000 → EXACT_MATCH), substring matching finds
the entity tables a question names but never the junction/bridge tables that
join them. Now the matched set is grown by **one foreign-key hop** in either
direction. Validated offline first (recall 0.702→0.864, 16 questions improved,
0 regressed), then live. Kept despite flat headline: strict improvement to
recall and to the policy-violation hard-gate metric; reverting regresses both.

### Round 2 — generation: prompt guidance (REVERTED)
Added a "getting the answer right" block to `GENERATE_SYSTEM` (enum/value
matching, audit-vs-business columns, soft-delete, chronological ordering).
Accuracy 36→26%, parse 98→88%, guard-pass 96→86% — the extra text crowded out
the schema for a small model. Reverted per the protocol; a one-line note remains
in the prompt file so it is not blindly re-added.

## Caveats

1. **Measurement noise.** At temp 0.2 the headline carries ~±4 pts of run-to-run
   variance (a MATCH flipped between baseline and Round 1 at *unchanged* recall),
   plus occasional ERROR outcomes from the Lightning free-tier rate limit. That
   is the magnitude of a 2-question delta, so single-run deltas near the noise
   floor are not trustworthy. The CI gate should run **temperature 0** (the seed
   script default).
2. **65% is not reachable by tuning here.** The honest levers are a stronger
   model (the nightly defaults to `gpt-4o-mini`) or value-linking (feeding real
   low-cardinality column values into the schema context — a connector change),
   not more prompt text.
